# hxyfront-62013 木结构榫卯构件测绘

源提示词编号：8

测绘人员可录入建筑名称、构件编号、木材种类、榫卯类型、截面尺寸、病害位置、变形情况和修缮建议；页面提供构件清单、榫卯类型筛选、病害标记、单栋建筑关系视角，并扩展**修缮派工**与**木料领退台**：业务规则、存储、操作三区分层承载。

## 技术栈

React 19 + Vite 7 + TypeScript（strict）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62013

## 分层结构

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 业务规则层 | `src/domain/` | 纯函数、纯类型，不依赖 React：派工准入、排队排序、领退与留量校验 |
| 存储层 | `src/store/` | `reducer.ts` 单一数据源与全部写入动作（判定全部委托规则层）；`store.tsx` 提供 Context + localStorage 持久化 |
| 操作层 | `src/components/` | 测绘构件清单、修缮派工队列、木料领退台三个操作区 |
| 演示数据 | `src/data/seed.ts` | 覆盖阻塞、排队、在制、库存占用等初始场景 |
| 规则验证 | `scripts/check-rules.ts`、`scripts/check-store.ts` | 纯规则断言 + reducer 端到端流程断言 |

## 业务规则

1. **派工准入**：构件存在未复核病害或含水率缺失时，申报后只能处于「待派工」，不得占用工位；补齐复核/含水率后自动晋升排队。
2. **唯一任务**：同一建筑同一构件仅保留一个未完工任务，重复申报被拒绝。
3. **工位排队**：工位冲突时队列按病害等级（严重 > 中等 > 轻微）、同等级按申报时间（早者优先）排序；非队首任务开工让位，工位占满时拒绝开工。
4. **领料开工**：领料数量超过可用库存（台账存量 − 领退净占用）、毛料截面不足净截面 + 每边 10mm 留量（允许长宽互换）、木种不一致时一律拒绝开工，拒绝原因写入任务旧记录。
5. **退料回补**：退料按实退数量回补可用库存，且不得超过该木料已领未退数量。
6. **重测重排**：已开工构件重测后版本号 +1，任务转为「待重排」并释放工位，全部旧记录保留；旧料退清后才能按新版数据重新排队。
7. **一致性**：库存统计由台账与领退流水实时推导（刷新按钮更新时间戳），领退台内置「构件清单 · 派工队列 · 库存统计」三方对账。
